# M2 界面

对应规划 §6 的 M2：正式界面 `MSBOOST-Launcher.exe`。界面和命令行 `msboostctl` 共用 M1 的核心代码（`internal/app`），界面只是另一个入口。

## 1. 完成内容

| 位置 | 内容 |
|---|---|
| 加速（主页） | 开始/停止加速；冒险岛正在运行时，停止前会先确认。加速中显示已运行时长、当前连接数和累计连接数。可以切换节点配置（加速中不能切换），有 Discord/Steam 开关。网络检测显示三项：当前出口 IPv4、当前到中转服务器延迟、当前到游戏服务器延迟 |
| 节点配置 | 列出 `configs\` 里的配置，标出当前配置和无效配置。可导入配置文件（已有同名但内容不同的文件时，询问是否替换），可从旧版启动器文件夹导入，可设为当前、删除、打开文件夹、刷新。窗口重新获得焦点时会自动刷新 |
| 游戏与加速项 | 加速对象：固定清单，5 组共 24 个进程，只读。Discord/Steam 开关，并列出各自的进程。全程测速目标：可修改，也可恢复默认 |
| 日志 | 实时日志，可按程序/核心/分流筛选。可打开日志文件夹、导出诊断包（不含节点密码）。分流核心自带的日志里提到组件名的地方改写为“分流核心” |
| 设置与关于 | 数据目录、最小化到托盘、退出程序。清理残留：卸载驱动、删除所有 `MSBOOST relay` 防火墙规则、删除运行时文件。版本、GPL 声明和开源组件列表（只有这里出现组件名） |
| 托盘 | 左键单击显示窗口。菜单有“显示主窗口”“开始/停止加速”“退出”。加速中图标变成橙色。托盘操作出错时，主窗口弹出并显示提示 |
| 窗口 | 点 × 隐藏到托盘，加速继续；加速中退出程序要先确认。再次打开程序会显示已在运行的窗口。和 `msboostctl` 共用核心锁，不会同时驱动核心 |
| 图标 | 使用网站的枫叶标志。`scripts/make-icons.ps1` 可从 `build/icons/*.svg` 重新生成全部图标 |

与规划的不同：规划写的是“关闭窗口确认”。现在改为关闭即隐藏到托盘，只在真正退出时确认。这和旧 BAT 的“运行期间请勿关闭本窗口”是同一个目的，但不会误关。

## 2. 与旧 BAT 的功能对照

| 旧 BAT | 新界面 |
|---|---|
| [0] 加载配置文件 | “节点配置”页：导入配置文件、设为当前；主页的节点配置下拉框 |
| [1] 启动 MSBOOST | 主页“开始加速”；托盘菜单“开始加速” |
| [2] 停止 MSBOOST | 主页“停止加速”；托盘菜单“停止加速” |
| [3] 检查 MSBOOST IP 地址 | 主页“网络检测”，三项输出的写法与 BAT 一致 |
| [Q] 退出启动器 | “设置与关于”页“退出程序”；托盘菜单“退出” |
| 主菜单显示当前配置、运行状态 | 主页和侧边栏状态；托盘图标与提示文字 |
| “切换配置前请先停止” | 加速中，配置切换处于禁用状态 |
| “运行期间请勿关闭本窗口” | 点 × 只隐藏到托盘 |
| SOCKS5 地址（跟随配置） | 不再需要：程序自动分流游戏连接，本地 SOCKS5 使用每次随机生成的凭据，不对外暴露 |

## 3. 实测步骤

用 CI 编出的 `m2-windows-x64` 测试包测试。

### 准备

1. 打开仓库的 Actions 页面，进入 `m2-ui` 分支最新一次通过的 `ci` 运行，在页面底部下载 `m2-windows-x64`。
2. 解压到一个新文件夹，例如 `F:\AI\Claude\MSBOOST启动器\_local\m2ci\`。里面应有 `MSBOOST-Launcher.exe`、`ProxyBridgeCore.dll`、`WinDivert.dll`、`WinDivert64.sys`、`SHA256SUMS.txt`，这几个文件要放在一起。
3. 退出冒险岛、官方 ProxyBridge、Netch 和 M1 的 `msboostctl`。

### 测试 1：启动与托盘

双击 `MSBOOST-Launcher.exe`，同意管理员权限提示。

- 窗口标题是“MSBOOST 启动器”；托盘里有白色枫叶图标。
- 主页没有红色提示（管理员权限、冲突等）。

### 测试 2：导入配置

- 在“节点配置”页点“导入配置文件…”，选网站下载的 `.json`。导入后它应显示为“当前”。
- 再试一次“从旧版启动器导入…”，选旧 BAT 所在的文件夹。
- 或者直接把 `.json` 放进程序旁边的 `configs` 文件夹，切回窗口后会自动出现在列表里。

### 测试 3：网络检测

先不开始加速，在主页点“开始检测”，记下三项结果；开始加速后再测一次。

### 测试 4：完整加速（核心验收）

1. 点“开始加速”。状态应变为“加速中”，托盘图标变成橙色。
2. 打开冒险岛，登录、进频道、换频道，玩一段时间。连接数应随游戏变化。
3. 加速中打开 Discord 开关，然后重开 Discord，确认语音正常。这一项验证规划 §4.3 的“开关可在加速中切换”。
4. 再把 Discord 开关关掉。

### 测试 5：停止

在冒险岛还开着的时候点“停止加速”，应先弹出确认。确认后状态变为“未加速”，托盘图标变回白色。

### 测试 6：窗口和托盘

1. 开始加速后点窗口的 ×，窗口应隐藏，加速继续，游戏不断线。
2. 左键单击托盘图标，窗口回来。
3. 用托盘菜单停止、开始加速。
4. 加速中用托盘菜单“退出”，应先确认；确认后程序退出，驱动卸载。

### 测试 7：单实例

程序运行时再双击一次 exe，不应出现第二个窗口，只把已有窗口显示出来。

### 测试 8：日志和诊断包

在“日志”页查看实时日志，试一下筛选。点“导出诊断包…”保存 zip，确认里面有 `system.txt`、`settings.json`、`configs.txt` 和 `logs\`，并且没有节点密码。

> 日志和诊断包里有节点地址，只发给 MSBOOST 客服，不要公开发布。

### 测试 9：清理

停止加速后，在“设置与关于”页点“清理”，记下报告内容。然后在管理员命令行里确认：

```bat
sc query WinDivert
netsh advfirewall firewall show rule name=all | findstr /C:"MSBOOST relay"
```

第一条应提示服务不存在，第二条应没有输出。

### 测试 10：文案

逐页看一遍：除了“关于”里的组件列表，界面上不应出现 mieru、ProxyBridge 等组件名。哪里的文字不清楚、不顺，请记下来。

### 回报

把每项测试的结果（通过/有问题）发过来。有问题时附上截图和当时的日志（`logs\launcher-日期.log`），日志不要公开发布。
