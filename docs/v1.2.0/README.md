# v1.2.0：可以选择用 TCP 还是 UDP 连接节点

## 1. 为什么做

启动器和节点之间一直只用 TCP。国内到境外的 TCP 在晚高峰常有丢包和延迟抖动，mieru 的 UDP 模式在一些网络下表现更好，在另一些网络下（运营商限制境外 UDP）反而更差。所以节点同时提供两种方式，由用户在启动器里选；UDP 不通时自动退回 TCP。

整体方案、节点和网站的改动、中转支持 UDP 以及全部真机测试，见 [UDP 传输整改计划](../MSBOOST-UDP传输整改计划.md)。本版是其中启动器的部分。

## 2. 改了什么

- **配置**：节点开了 UDP 时，`直连.json` 在 TCP 绑定之后加一个同端口的 UDP 绑定，`trafficPattern` 带 `nonce.applyToAllUDPPacket=true`。只有 TCP 绑定的配置照旧。
- **加速页**：“节点配置”一行右边加 TCP / UDP 切换，只在当前配置带 UDP 时显示；加速中不能切换。设置项 `transport` 默认 TCP。
- **只用选中的那种**：mieru 客户端每建一条底层连接都从全部绑定里随机挑一个，两个都留着就会混用。所以启动核心前只保留选中的绑定，磁盘上的配置不变。
- **UDP 预检和退回**：选 UDP 时，核心起来后先经本地 SOCKS5 向节点的 `127.0.0.1:20424` 发一次 hello，最多 5 秒。失败就关掉核心、改用 TCP 重启，日志写明原因，并提示用户。设置保持 UDP。
- **状态栏**：加速中显示“经 TCP 连接节点”或“经 UDP 连接节点”。
- **网络检测**：按所选方式运行，并写明用的是哪种。选 UDP 时，如果出口 IP 和到游戏服务器都失败、而同一端口的 TCP 握手正常，就提示“经 UDP 连不上节点，可能是节点没有放行 UDP，或本机网络限制了 UDP；可改用 TCP”。
- **节点配置页**：入口后面标出“支持 UDP”。
- **msboostctl**：增加 `transport tcp|udp`（开发和测试用，不在发布包里）。
- **mieru v3.39.0**：服务端可以关闭空闲的 TCP 底层连接，出站流量少分配内存；启动器用到的客户端接口没有变化。

## 3. 兼容

- 只有 TCP 的旧配置：没有切换，行为和 v1.1.2 相同。
- 带 UDP 的新配置交给 v1.1.2 及更早的版本：它们不筛选绑定，会把 TCP 和 UDP 混用。所以要先发本版，网站（v2.11.0）再开始生成带 UDP 的配置，网站下载处也提示需要 v1.2.0 或更新版本。
- 加速过程中 UDP 断了不会自动切换，要停止后重新开始。要不要做加速中自动切换，等有用户反馈再定。

## 4. 实测

全部记录见整改计划的 10.4 和 11.8。启动器部分：

| 测试 | 结果 |
|---|---|
| 网络检测，三台节点（凌晨） | TCP 和 UDP 都可用，延迟基本相同；旧配置（只有 TCP）照常可用；旧配置选 UDP 时自动走 TCP |
| 选 UDP 开始加速（CI 构建版 dev-c6f9386，管理员身份） | 走 UDP，节点侧计数确认 |
| 节点丢弃 UDP 时开始加速 | 约 5 秒后提示并改用 TCP；节点侧只有 TCP 包增加 |
| UDP 恢复后再开始 | 重新走 UDP |
| 网络检测走 UDP 被拦 | 原先误报“节点未提供兼容的版本 2 全程 TCP 测速服务”，已改为提示 UDP 被拦 |
| 经本站两跳中转加前置机 | 客户端用下载的配置走 TCP 和 UDP 都能到节点 |
