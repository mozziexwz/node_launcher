# v1.1.2：网络检测和诊断包加入本机 DNS 检测

## 1. 为什么做

2026-10-26，开发者的电脑挂机一晚后游戏崩溃。重新打开时，Nexon 登录器转圈很久；进了游戏也登录不了，弹出 “Having trouble logging in?”。排查结果：

- 路由器的 DNS 转发从 10:32 起停了（Windows 系统日志，DNS Client 事件 1014）：先是国外域名全部超时，后来国内域名也超时。路由器上游的运营商 DNS 一直正常，重启路由器后恢复。
- 反作弊的认证域名 `x-csauth.ngs.nexon.com` 在 10:32、10:37、10:49 解析超时，10:52 游戏连接断开。
- 之后再登录，游戏登录要用的 `us-sso.nexon.io`、反作弊更新用的 `x-update.ngs.nexon.com`、登录器的 `ccu-edge.nexon.io` 都解析不了，游戏连都没有发起。MSBOOST 的日志里只看到反作弊组件每 12 秒一次的本机重试。
- 登录器大部分请求走系统代理，被 MSBOOST 接管后由节点解析域名，所以还能打开，只是慢。

MSBOOST 只接管连接，不接管 DNS 查询（规划 §1.2：不改系统 DNS）。本机 DNS 坏掉时，加速帮不上忙，而当时的日志和诊断包里都看不出原因，只能在电脑上手动查。这一版把这项检查做进网络检测和诊断包。加速规则不变。

## 2. 改了什么

### 网络检测新增第四项“本机 DNS 解析游戏域名”

- 查这 4 个域名（`internal/profiles` 的 `GameDomains`）：

  | 域名 | 用途 |
  |---|---|
  | `us-sso.nexon.io` | 游戏登录 |
  | `x-csauth.ngs.nexon.com` | 反作弊 |
  | `ccu-edge.nexon.io` | 登录器在线状态 |
  | `config.na.nexon.com` | 游戏配置 |

- 结果：
  - 全部解析成功：“正常（最慢 xx ms）”；
  - 有失败：“解析失败（4 个中 n 个）”，鼠标悬停列出失败的域名和原因（超时、查不到这个域名、DNS 服务器没有给出结果等）；
  - 后面显示本机使用的 DNS 服务器。
- 对照：同时向 223.5.5.5 和 119.29.29.29 查询，任一个回答即可：
  - 只有本机失败：提示“本机 DNS（…）解析不了游戏域名，公共 DNS 能正常解析……请把网卡的 DNS 改为 223.5.5.5 和 119.29.29.29，或者重启路由器”；
  - 公共 DNS 也失败：提示可能是网络没有连通，或者 Nexon 的服务出了问题，不建议改 DNS；
  - 本机和公共 DNS 都“查不到这个域名”：当作 Nexon 已停用这个域名，不算失败。
- 加速页：DNS 检测失败时，顶部显示“本机 DNS 解析不了游戏域名，游戏可能登录不了。”和“详情”按钮。检测摘要那一行不变。
- 日志：网络检测那一行末尾加“本机 DNS …”；失败时列出失败的域名，以及公共 DNS 能否解析。

### 诊断包

- `system.txt` 增加 DNS 检测：总结果和 DNS 服务器；每个域名本机和公共 DNS 各自解析出的地址和用时；失败时附处理建议。
- 导出时要先做这次检测，导出期间按钮显示进行中。

## 3. 实现要点

- **本机解析**用 Go 的默认解析器。在 Windows 上它调用 GetAddrInfoW，和游戏一样经过 hosts、DNS 缓存和网卡上的 DNS 服务器。只查 IPv4。
- **公共 DNS**用 Go 自带的解析器，直接向 223.5.5.5、119.29.29.29 的 53 端口发请求，不经过本机的 DNS 设置。两个同时问，先回答的为准。
- **时长**：所有查询同时进行，最多 5 秒（Windows 自己处理一次失败的查询要 10 秒左右）。网络检测里它和另外三项同时跑，不增加总时长。
- **DNS 服务器列表**用 GetAdaptersAddresses 读取（和 v1.1.1 的网卡信息相同），不读注册表，不启动外部命令。
- MSBOOST 启动器自己不在加速名单里，这些查询不会被分流，也不会交给节点。

## 4. 实测步骤

1. 本机 DNS 正常时做网络检测：第四行显示“正常（最慢 xx ms）”，后面是 DNS 服务器。
2. 让本机 DNS 解析不了国外域名（例如路由器 DNS 出故障，或把网卡 DNS 临时改成一个不回应的地址），再检测：
   - 第四行红色“解析失败（4 个中 4 个）”，下方黄色提示建议改 DNS 或重启路由器；
   - 鼠标悬停列出 4 个域名“超时”；
   - 另外三项照常出结果；
   - 加速页顶部出现提示，点“详情”跳到网络检测页。
3. 导出诊断包：按钮转圈几秒；`system.txt` 有“本机 DNS 解析游戏域名”几行。
4. 日志页：网络检测那一行末尾有“本机 DNS …”。
5. 对比 v1.1.1 和本版程序的字符串：没有新增容易被误报的写法。

## 5. 实测结果

| 测试包 | 日期 | 结果 |
|---|---|---|
| dev-a51aeb1 | 2026-10-26 | 实测通过，见下 |

- 路由器 DNS 故障时，4 次检测都显示“解析失败（4 个中 4 个）……公共 DNS 能解析”，另外三项照常出结果。
- 修好路由器后，6 次检测（含 1 次加速中）都显示正常；游戏经节点正常登录（`us-sso`、`x-csauth`、`login-mscw`）。
- 诊断包 `system.txt` 里的 DNS 检测内容正确。
- 和 v1.1.1 对比程序字符串：注册表代理设置名、结束进程、注册表读写等字样的数量完全相同，新增的只有 223.5.5.5 和 119.29.29.29。

## 6. 以后再考虑

- 让节点解析游戏域名：只接管 Nexon 域名的 DNS 查询交给节点，节点查不到再回落到本机 DNS。这样本机 DNS 坏掉时也能玩，但要给分流核心加补丁、确认节点放行 53 端口，并重新评估报毒风险。这一版先只做检测。
