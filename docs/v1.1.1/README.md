# v1.1.1：诊断信息补全（加速逻辑不变）

## 1. 为什么做

2026-10-24 起，一位玩家（小米笔记本 + 手机热点，Windows 11）反馈：加速开着，Nexon 登录器一直转圈；重启电脑、关开加速几次后有时又能用。用他的诊断包排查时，缺几项关键信息，只能靠猜：

- 登录器到底有没有发起连接，连的是 IPv4 还是 IPv6；
- 交给节点的是域名还是 IP，节点有没有回应；
- 电脑当时的网络环境：网卡、IPv6、DNS、系统代理；
- 开始加速时界面上的提醒（游戏已在运行、冲突），日志里没有。

这一版只补诊断信息，加速规则和流程都不变。

## 2. 改了什么

### 连接记录（日志新增“连接”分类）

- **名单内程序的新目标**：加速期间，名单内程序（以及已开启的 Discord、Steam）每访问一个新目标，记一行：程序名、TCP 或 UDP、是否 IPv6、目标地址和端口、处理方式（加速、直连、拦截，或“改由 MSBOOST 接管（系统代理）”）。同一程序访问同一目标只记一次。
- **交给节点的连接**：每条连接结束时，记下交给节点的目标（域名，或者没拿到域名时的 IPv4/IPv6 地址）、上行和下行字节数、用时。上行有数据而下行是 0 的，标注“没有收到任何回应”。同一目标只记一次，没有回应的另记一次。网络检测自己的探测不记。
- **上限和统计**：每次加速两类各最多记 200 条。停止加速时写一行统计：访问的目标数（加速、直连、拦截，其中 IPv6 多少）；经节点的连接数（域名、IPv4 地址、IPv6 地址），其中多少条没有回应；超过上限没写出的条数。
- **只记名单内程序**：浏览器、聊天软件等其他程序的连接一律不记。
- 日志页新增“连接”筛选。

### 开始加速时写进日志

- **网络环境**：Windows 版本；系统代理（包括自动配置脚本）；每块正在使用的网卡的类型、IPv4/IPv6 地址、网关和 DNS。电脑自己的公网地址只显示前半段（IPv4 前三段，IPv6 前两组），能看出网络类型和运营商，但不暴露具体地址。
- **提醒**：开始加速前游戏已在运行、不阻止加速的冲突（例如 Netch 在运行）。以前只显示在界面上。

### 诊断包

`system.txt` 增加：
- 网络环境（同上）；
- 游戏相关进程：名单内正在运行的进程，以及名字里有 nexon、maple 但不在名单里的进程。后者用来发现登录器更新后改了进程名。

## 3. 实现要点

- **连接决定**来自分流核心自带的连接回调。回调运行在唯一的收发包线程上，Go 这边只复制字符串放进队列，不做别的事。开启回调前打开分流核心的按目标去重，同一程序同一目标只回调一次。回调指针没有加锁，所以只在开始加速前设置、在分流核心完全停止后清除，加速途中不动它。
- **交给节点的连接**来自核心的本地 SOCKS5 入口：在原有的连接计数外再包一层，读出握手里的请求目标（账号密码直接跳过，不保存），之后只统计字节数。不改任何数据，也不拖慢转发。停止加速时最多等 2 秒，让还开着的连接写完记录再写统计。
- **网卡信息**用 GetAdaptersAddresses 读取，系统代理沿用 WinHTTP 接口。不读注册表，不启动外部命令，避免杀毒软件和 Chrome 误报。
- 不改分流核心的 C 代码，不改加速规则。

## 4. 实测步骤

1. 开始加速，打开 Nexon 登录器并进入游戏，玩几分钟后停止加速。
2. 日志页切到“连接”：
   - 有 nexon_launcher.exe、MapleStory.exe 等的连接，处理方式是“加速”；
   - 有“经节点 …（域名）”的记录和字节数；
   - 停止后有“本次统计”。
3. 日志页切到“程序”：开始加速时有“网络环境”和“网卡 …”几行。
4. 导出诊断包：`system.txt` 里有网络环境和游戏相关进程。
5. 开着 v2rayN 的系统代理再加速一次：连接记录里有“改由 MSBOOST 接管（系统代理）”。
6. 加速中打开 Steam 可选加速：打开之后，steam.exe 的连接才开始被记录。
7. 对比 v1.1.0 和本版程序的字符串：没有新增注册表里的代理设置名、按名字结束进程这类容易被误报的写法。
