# 节点放行清单整改计划

> 日期：2026-10-17
> 修改位置：MSBOOST 项目（MSBOOST.DE）`installers/node/msboost.sh` 中的节点放行清单 `msboost-direct`（第 676–807 行；安装到节点后是 `/etc/msboost/ruleset/msboost-direct.yaml`）
> 起因：MSBOOST 启动器 v1.0.2 排查“Nexon 登录器偶尔在 LOG IN 时一直转圈”（本目录 `README.md` 第 4 节）

## 1. 背景

节点按顺序匹配三条规则：
1. `msboost-direct`（放行清单）：直连；
2. `msboost-filter`（GFW 域名列表，每天从 MetaCubeX 下载）：拒绝；
3. 其余：直连。

- 只有以**域名**交给节点的连接才会被第 2 条拦，以 IP 交给节点的不会。
- MSBOOST 启动器开启了“发送域名”，所以加速的程序访问 GFW 列表里的域名时，有时被拒、有时通过。
- GFW 列表每天更新，会有域名加入或移出。游戏必需的域名应该放进放行清单，不依赖列表的变化。
- `nexon.com` 本身就在 GFW 列表里，Nexon 能用全靠放行清单。

## 2. 要添加的规则

### 2.1 必须添加

| 规则 | 用途 |
|---|---|
| `DOMAIN,www.gstatic.com` | 谷歌人机验证（reCAPTCHA）的脚本和样式 |

依据：
- Nexon 账号登录页（`www.nexon.com/account/.../login`）先从 `recaptcha.net` 加载 `api.js`，`api.js` 再从 `www.gstatic.com/recaptcha/releases/…` 加载验证脚本和样式。
- 点 LOG IN 时要先拿到人机验证结果；脚本加载失败，按钮就一直转圈。
- 经节点实测（完成 TLS 握手才算连通）：以域名交给节点时失败（连接被关闭），以 IP 交给节点时成功。
- 只放行 `www.gstatic.com` 这一个主机，不放行整个 `gstatic.com`，也不放行 `google.com`。

### 2.2 建议添加（预防）

| 规则 | 用途 | 理由 |
|---|---|---|
| `DOMAIN-SUFFIX,recaptcha.net` | 人机验证主域名 | 目前不在 GFW 列表；它只用于人机验证，一旦被列入，登录会再次转圈 |
| `DOMAIN-SUFFIX,nexonstatic.com` | Nexon 静态资源（`g.nexonstatic.com`，游戏和登录器的图片等） | 目前不在 GFW 列表，但 M0 测试和 2026-10-16 的日志里各被拒过一次；属于 Nexon 自有域名，和已放行的 `nexon.com` 等一致 |

### 2.3 修改示例

在 Nexon 段的 `- DOMAIN-SUFFIX,nexongames.co.kr` 之后加一行，并在 Steam 段之前加一段：

```yaml
  - DOMAIN-SUFFIX,nexongames.co.kr
  - DOMAIN-SUFFIX,nexonstatic.com
  # ……（原有内容不变）……
  - DOMAIN-SUFFIX,sdo.com

  # reCAPTCHA on the Nexon account login page: api.js on recaptcha.net loads
  # its script and styles from www.gstatic.com. Only that host is allowed,
  # not the rest of gstatic.com or google.com.
  - DOMAIN-SUFFIX,recaptcha.net
  - DOMAIN,www.gstatic.com

  # Steam and first-party Valve services.
```

同时把清单开头的 `# Reviewed snapshot: 2026-09-09.` 改成 `2026-10-17`。

## 3. 不需要添加的

下面这些会被节点拦，但不影响游戏，也不影响账号密码登录：

| 域名 | 出现位置 | 不加的理由 |
|---|---|---|
| `fonts.gstatic.com` | 人机验证框的 Roboto 字体 | 加载失败只会换成默认字体 |
| `region1.analytics.google.com` | 登录页的谷歌统计 | 仅统计 |
| `connect.facebook.net` | 登录页的 Facebook SDK 和广告统计 | 只影响 Facebook 登录（第 4 节） |
| `google.com` | 游戏内覆盖层（`DwarfAxe.exe`）创建浏览器时预加载的页面 | 只是预热；以前直连时也打不开 |
| `tenor.com`、`tenor.googleapis.com`、`youtube.com`、`ytimg.com` | Discord 的 GIF 搜索和聊天里嵌入的视频（开启 Discord 加速时） | 非必需；YouTube 是主要的被拦网站 |

## 4. 可选：第三方账号登录（需要你决定）

登录页上的 Google、Facebook、X 登录按钮要访问被拦的网站。Apple 登录相关的域名（`appleid.apple.com` 等）不在 GFW 列表，现在就能用。

| 登录方式 | 需要的主要域名（目前会被拦） |
|---|---|
| Google | `accounts.google.com`、`ssl.gstatic.com`、`apis.google.com`、`play.google.com`、`lh3.googleusercontent.com`、`fonts.gstatic.com` 等 |
| Facebook | `www.facebook.com`、`m.facebook.com`、`static.xx.fbcdn.net`、`connect.facebook.net` 等 |
| X | `x.com`、`api.x.com`、`twitter.com`、`api.twitter.com`、`abs.twimg.com`、`pbs.twimg.com` 等 |

建议默认不放行：
- 节点配置在玩家手里，可以不经启动器直接使用节点。放行这些域名，等于让节点能访问这些网站的部分页面，违背节点过滤 GFW 域名的初衷。
- 加速时请玩家用 Nexon 账号密码或 Apple 账号登录。
- 如果确实要支持，需要先逐个实测出最小的域名集合，再只放行这些精确的主机名（`DOMAIN`）。

## 5. 复查范围与结论

复查范围：
- 诊断日志中出现过的全部域名（22 个）；
- 登录器（`nexon_client` 的 `app.asar`）、游戏和各组件、反作弊、MapleStory Worlds 里出现的全部网址；
- Nexon 登录页和人机验证框实际加载的域名；
- Steam、Discord 两个可选加速项的常用域名。

结论：

| 类别 | 结论 |
|---|---|
| Nexon 各域名：`us-sso.nexon.io`、`login.maplestory.nexon.net`、`public.api.nexon.com`、`download2.nexon.net`、`config.na.nexon.com`、`guard.nexon.net`、`psm-log.ngs.nexon.com`、`*.nxfs.nexon.com` 等 | 已被 `nexon.com`、`nexon.net`、`nexon.io` 覆盖，实测连通。日志里它们的失败全部发生在 2026-10-16 02:53–02:56 节点连接整体中断期间，不是被节点拒绝 |
| 地区检查接口（`*.execute-api.*.amazonaws.com`）、`recaptcha.net`、谷歌统计和 GTM、OneTrust Cookie 提示、Sentry | 不在 GFW 列表，直连 |
| 反作弊（BlackCipher、NGS-X）、MapleStory Worlds | 没有发现会被拦的域名。MapleStory Worlds 的谷歌登录走系统浏览器，不经过节点 |
| Steam（可选加速） | 主要域名都在放行清单 |
| Discord（可选加速） | 主要域名都在放行清单；登录用的 hCaptcha 不在 GFW 列表 |
| 程序里出现的其他被拦域名（`*.github.io`、`goo.gl`、`youtu.be`、`googleapis.com` 等） | 只出现在开源库的说明文档或示例代码里，不会访问 |

## 6. 部署与验收

部署：
- 放行清单是节点上的文件型规则，修改安装脚本只影响新安装的节点。
- 已部署的节点要更新 `/etc/msboost/ruleset/msboost-direct.yaml` 并重启节点服务，或走你的节点更新流程，新规则才会生效。

验收：
1. 用 MSBOOST 启动器开始加速，在 Nexon 登录器里退出账号，再用账号和密码手动登录，应能顺利登录。开着、关着 v2rayN 系统代理各试一次。
2. Steam 版也做一次同样的测试。
3. 可选：告诉我已更新的节点，我用同样的方法（经节点做 TLS 握手）复测 `www.gstatic.com`。
