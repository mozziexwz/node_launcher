# v1.0.1：兼容其他代理软件，一键停止 ProxyBridge

## 1. 改了什么

### 兼容 v2rayN、Clash 等软件的“系统代理”

**问题**：v2rayN 开启系统代理且节点不在美国时，登录器点“PLAY”会提示“Gameplay is not currently supported for either your current location…”。
- 原因：系统代理指向本机端口（如 `127.0.0.1:10808`），登录器把请求发给它；分流核心对发往本机的连接一律直连，于是地区检查走了 v2rayN 的节点。
- 详细分析见规划 §4.8。

**修改**：
- 开始加速时读取 Windows 的系统代理设置，包括 PAC 模式。
- 游戏（以及已开启的 Discord/Steam）发往系统代理的连接，改由 MSBOOST 内置的“代理请求处理器”接管：它代替那个软件回应游戏，再把真实请求从 MSBOOST 节点发出。
- 其他软件照常使用它们的代理。
- 加速中每 5 秒检查一次，开关代理软件后会自动跟上。
- 主页加速中会显示“已接管系统代理 127.0.0.1:10808”，日志里会记录被接管的请求地址。

**实现**：
- `internal/sysproxy`：读取设置，以及代理请求处理器本身。
- `internal/app/sysproxy.go`：把接管接入加速流程。
- 分流核心补丁 P4（`third_party/patches/0002-localhost-proxy-ports.patch`）：允许按规则代理指定的本机端口。

**测试**：
- 系统代理各种写法的识别：单一地址、按协议分开、带 `http://`、`localhost`、IPv6、局域网主机、PAC 脚本。
- 代理请求处理器：
  - 支持 HTTP CONNECT、普通 HTTP 请求（同一连接连续多个）、SOCKS5（有无认证）、SOCKS4a；
  - 拒绝 UDP；
  - 前端错误密码被拒绝；
  - 连接失败时返回 502；
  - 关闭时结束所有连接。
- 控制器：
  - 接管规则排在游戏规则之前；
  - 加速中系统代理关闭、换端口时规则原地更新；
  - 开关 Discord 时同步进程列表；
  - 停止后不留规则、代理配置和监听端口。
- CI 用自编的分流核心检查 P4 接口确实存在。

### ProxyBridge 冲突一键处理

检测到 ProxyBridge 的后台服务或程序正在运行时，提示条上有 **“停止 ProxyBridge”** 按钮。点击并确认后：
- 程序向 ProxyBridge 的窗口发送它托盘菜单里的“退出”命令，让它自己正常退出（同时停掉它的分流核心），而不是强行结束进程；
- 再停止 `ProxyBridgeSvc` 服务，然后报告做了什么。

如果 8 秒内它没有退出（例如旧版本或命令行版），会提示你从托盘手动退出。ProxyBridge 如果设置了开机启动，下次开机还会运行；不再使用的话，建议卸载它。

### Chrome 拦截下载（“已屏蔽危险的下载内容”）

第一版测试包（dev-3cb3bff）在 Chrome 中被判为危险下载，而 v1.0.0 没有。对比两版程序里的字符串后发现，v1.0.1 新增了两类恶意软件常见的特征：
- 直接读取注册表里的浏览器代理设置（`Internet Settings`、`ProxyServer`、`ProxyEnable`、`AutoConfigURL`）。劫持浏览器流量的木马就是改这几项。
- 按进程名找到并强行结束其他程序（“强杀杀毒软件”类恶意软件的做法）。

修改：
- 改用浏览器同样使用的系统接口 `WinHttpGetIEProxyConfigForCurrentUser` 读取代理设置；
- 停止 ProxyBridge 时改为请它正常退出。

改完后，以上字符串都回到了 v1.0.0 的水平。Chrome 的判断是谷歌的启发式规则，并不公开，所以最终以实际下载为准。如果仍被拦截，长期办法是给程序做代码签名，或者向谷歌提交误报。

### 刚关闭其他分流软件后立即开始加速

第二个测试包（dev-8aee9e6）实测时发现一个问题：MSBOOST 加速期间又启动了官方 ProxyBridge，两者共用同一个分流驱动（WinDivert）。
- 停止 MSBOOST 时，驱动因为还被 ProxyBridge 占着，卡在“正在停止”。
- 关掉 ProxyBridge 后，驱动又过了约 50 秒才彻底卸载。这期间开始加速都失败了，分流核心报错 1058。原因是正在卸载的驱动服务会被系统标记为禁用。

修改：开始加速前检查驱动是否还在卸载，是的话自动等待（最多 60 秒，日志会说明），卸载完再继续。超时时给出明确的提示，不再只显示“分流启动失败”。

## 2. 实测步骤

用 CI 编出的测试包测试。
1. 在 Actions 页面打开最新一次通过的运行，下载 `MSBOOST-Launcher-dev-xxxxxxx-windows-x64`。先确认 Chrome 不再提示“已屏蔽危险的下载内容”（测试 0）。
2. 解压到新文件夹，把节点配置复制进 `configs`，或者用“导入配置文件”。

### 测试 1：开着 v2rayN 的系统代理玩游戏（核心验收）

1. v2rayN 选一个**不在美国**的节点，打开“自动配置系统代理”。
2. 打开 MSBOOST 启动器，开始加速。主页应显示“已接管系统代理 127.0.0.1:10808”（端口以你的 v2rayN 为准）。
3. 打开 MapleStory 登录器，点 PLAY。应能正常进入游戏，不再提示地区不支持。
4. 在“日志”页应能看到“检测到系统代理 …”和“游戏经系统代理的请求已改由 MSBOOST 发出：…”。

### 测试 2：其他软件不受影响

在加速中，用浏览器打开一个查询 IP 的网站。显示的应是 **v2rayN 节点**的 IP，说明浏览器仍然走 v2rayN，MSBOOST 只接管了游戏。

### 测试 3：加速中开关代理软件

1. 加速中把 v2rayN 的系统代理改成“清除系统代理”。约 5 秒内，日志出现“系统代理已关闭”，主页上的接管提示消失。
2. 再改回“自动配置系统代理”。约 5 秒内，日志出现“检测到系统代理 …”。

### 测试 4（可选）：Clash 系列

如果装有 Clash Verge Rev、Mihomo Party 等，开启它们的系统代理（不要开 TUN 模式），重复测试 1。

### 测试 5：一键停止 ProxyBridge

1. 打开官方 ProxyBridge，让它的服务运行起来。
2. 打开 MSBOOST 启动器，主页应出现红色提示和“停止 ProxyBridge”按钮。
3. 点击按钮并确认，应显示“已让 ProxyBridge 程序退出”“已停止 ProxyBridge 后台服务…”（只开了服务时只有后一条），红色提示消失，可以开始加速。

### 测试 5b：关闭 ProxyBridge 后立即开始加速

1. MSBOOST 开始加速，然后打开官方 ProxyBridge。
2. 停止 MSBOOST 加速，再点“停止 ProxyBridge”。
3. 立即点“开始加速”。如果驱动还在卸载，日志会显示“分流驱动还在卸载……正在等待”，等它卸载完会自动继续，而不是直接失败。

### 测试 6：没有其他代理软件时照常加速

关闭 v2rayN，正常开始加速、进游戏，确认一切和 v1.0.0 一样。
