# v1.0.3：加速页统计行不再一行两行来回跳

## 1. 问题

加速中，“已运行 / 已使用流量 / 当前速率”这一行有时是一行，有时“当前速率”跑到第二行，过一会儿又恢复成一行。

## 2. 原因

- 这一行用的是“放不下就换行”的排版，而数值文字的长短一直在变，比如速率从 `468 B/s` 变成 `47.77 KiB/s`。
- 默认窗口下这一行的可用宽度是 503 px，平时需要 485–508 px，正好卡在临界点：速率一变长就换行，变短又回到一行。

在默认窗口大小下实测：

| 数值 | 需要的宽度 | 结果 |
|---|---|---|
| ↑ 468 B/s、↓ 2.77 KiB/s 等 | 485 px | 一行 |
| ↑ 47.77 KiB/s、↓ 4.77 KiB/s 等 | 508 px | 两行 |
| 最长（100 小时、1023.99 MiB、1023.99 KiB/s） | 572 px | 两行 |

## 3. 修改

- 每个数值都按它可能出现的最长文字预留宽度（`frontend/src/components.tsx` 中的 `Steady`），这一行的宽度不再随数值变化。
- 收紧排版，让最长的数值在默认窗口下也能放进一行：
  - 统计文字 14px → 13px；
  - 项目间距 22px → 16px，上下行速率之间 10px → 8px；
  - 加速卡片的左右内边距 28px → 24px，卡片内间距 24px → 20px；
  - “开始加速 / 停止加速”按钮的最小宽度 168px → 140px。

结果：
- 默认窗口固定一行：需要 529 px，可用 543 px；
- 窗口缩窄到放不下时固定两行，速率在第二行；
- 数值怎么变都不会再跳。

## 4. 实测步骤

1. 用测试包开始加速，观察这一行：速率在 B/s、KiB/s 之间变化时，应一直保持一行。
2. 可选：让速率到 MiB/s 级别，比如在登录器里下载补丁，仍应保持一行。
3. 把窗口拉到最窄：应固定两行，不来回跳。
